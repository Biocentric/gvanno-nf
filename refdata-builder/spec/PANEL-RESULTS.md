# 1,250-variant validation panel — bundle `20260801` vs `20231224`

Run 2026-08-01 on hephaestus, GRCh38, `sigven/gvanno:1.7.0` unchanged, same
VEP 110 cache for both. Panel generated by
[`verify/make_check_panel.py`](../verify/make_check_panel.py) (seeded, so it
reproduces exactly).

The 11-variant fixture was not enough. It is mostly somatic hotspots, and it
caught nothing when PCGR's ClinVar turned out to be dropping germline
records — only a hand check of F5 Leiden did. This panel is the systematic
replacement.

## Panel composition

250 variants in each of the five ClinVar tiers, one variant per gene per tier,
SNVs with a real ALT only, spanning all 24 chromosomes. Sampled from the
**prior** bundle's ClinVar, so every variant is known to have been annotatable
before — anything missing afterwards is a real regression, not an artefact of
how the input was chosen. Each carries `EXPECT_MSID` / `EXPECT_CLASS` /
`EXPECT_GENE` in its INFO so the comparison asserts per variant rather than
counting non-empty columns.

## Result

| | `20231224` | `20260801` |
|---|---|---|
| rows out | 1250 | 1250 |
| ClinVar ID matched | **1250 (100%)** | **1245 (99.6%)** |
| ClinVar ID *wrong* | 0 | **0** |
| not annotated | 0 | 5 |

**Zero variants received the wrong ClinVar ID.** That is the load-bearing
result: the annotation path is intact, not merely populated.

### The five losses are upstream, not ours

| MSID | locus | expected class |
|---|---|---|
| 369307 | 2:113059094 G>A | VUS |
| 334305 | 2:218270457 C>A | VUS |
| 303048 | 11:121292700 T>G | VUS |
| 316858 | 15:67066040 C>T | Likely_Benign |
| 376389 | 20:20052443 G>A | Likely_Pathogenic |

Each was checked against the NCBI ClinVar `20260728` source by VariationID and
by locus: **all five are absent from ClinVar itself**, and nothing sits at
those positions either, so they were retired rather than merged. 5 of 1250
(0.4%) over 2.5 years is ordinary ClinVar record turnover.

## Coverage

| Column | `20231224` | `20260801` | |
|---|---|---|---|
| `CLINVAR_PMID` | 502 | **733** | +46% |
| `EFFECT_PREDICTIONS` | 751 | **792** | +41 |
| `NCER_PERCENTILE` | 1243 | 1243 | unchanged ✓ |
| `SYMBOL` | 1249 | 1249 | unchanged ✓ |
| `CLINVAR_MSID` | 1250 | 1245 | −5 (above) |
| `DBNSFP_SIFT` | 508 | 502 | −6 |

`NCER_PERCENTILE` and `SYMBOL` holding exactly steady is the control: ncER is
carried forward byte-for-byte and `SYMBOL` is VEP-derived, so any movement
there would have meant the rebuild corrupted something.

The `DBNSFP_SIFT` dip is v5.3 having marginally different SIFT coverage from
v4.5. `EFFECT_PREDICTIONS` rose over the same variants, so there is no net
loss of prediction.

## Reclassification — the reason to ship

| Expected class | unchanged | reclassified | unannotated |
|---|---|---|---|
| Pathogenic | 226 | **24** | 0 |
| Likely_Pathogenic | 205 | **44** | 1 |
| VUS | 246 | 1 | 3 |
| Likely_Benign | 245 | 4 | 1 |
| Benign | 246 | 4 | 0 |

**77 of the 96 reclassifications fall in the two pathogenic tiers.** That
asymmetry is what you would expect and want: evidence accumulates on candidate
pathogenic variants and ClinVar moves them, while the benign end and VUS stay
nearly static.

Concretely: **68 of 500 pathogenic-tier calls (13.6%) change** between the 2023
and 2026 bundles. That is the cost of running stale ClinVar in a germline
clinical annotator, measured rather than asserted.

## Reproducing

```bash
python3 refdata-builder/verify/make_check_panel.py \
    --clinvar <prior bundle>/data/grch38/variant/vcf/clinvar/clinvar.vcf.gz \
    --out panel.grch38.vcf --per-class 250 --assembly GRCh38

nextflow run . -profile docker --input panel_samplesheet.csv --genome GRCh38 \
    --refdata_dir <bundle> --refdata_version <version> --outdir <out>
```
